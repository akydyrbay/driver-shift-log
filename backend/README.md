# API и JSON-хранилище

Из каталога `backend/`:

```bash
uv sync --locked
uv run --locked uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

`GET /health` возвращает `{"status":"ok"}`. При запуске проверяется файл поездок;
существующий повреждённый файл приводит к ошибке запуска и не перезаписывается.

## Данные и настройки

По умолчанию используется `backend/data/trips.json`, независимо от рабочего каталога.
Переменная `TRIPS_FILE` задаёт другой путь (относительный путь отсчитывается от
рабочего каталога процесса):

```bash
TRIPS_FILE=/tmp/driver-shift-log/trips.json uv run --locked uvicorn app.main:app
```

Отсутствующий файл означает пустое хранилище; файл и родительские каталоги создаются
при первом добавлении. Для пустого существующего хранилища используйте JSON-массив
`[]`, а не файл нулевой длины. Файл примера автоматически не копируется.

`Trip` проверяет обязательные поля `id`, `start`, `end`, `amount`, `payment`,
`commission`. Время передаётся в ISO 8601 с часовым смещением; окончание должно быть
позже начала в абсолютном времени. Суммы — целые числа: `amount > 0` и
`0 <= commission <= amount`. Допустимые способы оплаты — `cash` и `card`.
Пустые идентификаторы, неизвестные поля и неявное преобразование сумм из строк,
дробей или логических значений отклоняются.

`JsonTripStore.list_trips()` читает и проверяет данные, `add_trip(trip)` добавляет
проверенную запись. Уже занятый `id` вызывает `DuplicateTripError`, содержащую
существующую поездку. HTTP-маршрут использует её для обработки повторной отправки.

Добавление блокирует всю операцию чтения, проверки и записи. Экземпляры хранилища
с одинаковым абсолютным путём используют общую блокировку в одном процессе.
Данные записываются во временный файл рядом с основным, сбрасываются на диск и
заменяют основной файл атомарно. Ошибка до замены сохраняет прежнее содержимое.
Запускайте сервер с одним worker: несколько процессов или контейнеров,
одновременно пишущих в один JSON-файл, не поддерживаются.

## Поездки и сводка за день

Оба маршрута требуют параметр `date` в формате `YYYY-MM-DD`. День определяется
по времени **начала** поездки, переведённому в `Asia/Almaty`. Поездка через полночь
целиком относится к дню начала. Исходное часовое смещение в ответе сохраняется.

```bash
curl --fail 'http://127.0.0.1:8000/api/trips?date=2026-10-01'
curl --fail 'http://127.0.0.1:8000/api/summary?date=2026-10-01'
```

`GET /api/trips` возвращает массив поездок со всеми полями `Trip`, отсортированный
по времени начала от ранних к поздним (при совпадении времени — по `id`).

Ответ `GET /api/summary` для файла примера:

```json
{
  "date": "2026-10-01",
  "trip_count": 2,
  "revenue": 3900,
  "commission": 585,
  "take_home": 3315,
  "cash_revenue": 1500,
  "card_revenue": 2400
}
```

`revenue` — выручка до комиссии; `commission` — сумма комиссий;
`take_home` — выручка за вычетом комиссии. `cash_revenue` и `card_revenue`
показывают выручку до комиссии по каждому способу оплаты.

Для дня без поездок возвращаются `[]` и сводка с нулевыми показателями.
Отсутствующая, невозможная или неверно отформатированная дата даёт HTTP 422.
Ошибка чтения или повреждение файла во время работы даёт HTTP 503 с сообщением
`Trip storage is unavailable`. Описание схем доступно в `/docs`.

## Добавление поездки

`POST /api/trips` принимает JSON-объект поездки:

```bash
curl -i 'http://127.0.0.1:8000/api/trips' \
  -H 'Content-Type: application/json' \
  -d '{"id":"t3","start":"2026-10-01T10:00:00+05:00","end":"2026-10-01T10:20:00+05:00","amount":2000,"payment":"cash","commission":300}'
```

- `201 Created`: новая поездка сохранена; тело ответа содержит сохранённую поездку.
- `200 OK`: поездка с тем же `id` и данными уже существует; возвращается исходная
  запись, файл не переписывается, сводка не меняется.
- `409 Conflict`: `id` уже занят поездкой с другими данными. Ответ:
  `{"detail":"Trip ID already exists with different data"}`. Исходная запись сохраняется.
- `422 Unprocessable Entity`: данные не прошли проверку. Массив `detail` содержит
  расположение ошибки (`loc`) и описание (`msg`). Например, нулевая сумма даёт
  `loc: ["body", "amount"]` и `msg: "Input should be greater than 0"`.
- `503 Service Unavailable`: запись не удалась; запрос можно повторить с тем же `id`.

Клиент создаёт `id` один раз и сохраняет его при повторных попытках отправки.
Разные `id` считаются разными поездками, даже если остальные поля совпадают.
Время сравнивается как момент времени: `08:10+05:00` и `03:10Z` для одной даты
эквивалентны. При повторе ответ сохраняет часовое смещение исходной записи.
Одновременные повторы в одном процессе также создают только одну запись.

## Тесты

```bash
uv run --locked python -m unittest discover -s tests -v
```

Проверяются валидация, чтение примера, сохранение и повторное открытие,
ошибки записи, повреждённые данные, настройка пути, запуск приложения и
одновременные добавления. API-тесты дополнительно проверяют дневные итоги,
пустые дни, границы дня в `Asia/Almaty`, порядок поездок и ошибки запросов,
создание, повторы, конфликты идентификаторов и одновременные POST-запросы.
Запись в тестах выполняется только во временных каталогах.
