# API и SQLite

Из каталога `backend/`:

```bash
uv sync --locked
uv run --locked python -m app.import_trips data/trips.json
uv run --locked uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Импорт нужен для загрузки примера или переноса существующих поездок. Его можно
повторять: идентичные записи пропускаются. Без импорта новая база будет пустой.
SQLite доступен через стандартный модуль Python `sqlite3`; отдельный сервер БД не нужен.

`GET /health` возвращает `{"status":"ok"}`. При запуске создаётся база, если её ещё
нет, и проверяются существующие записи. Повреждённая база приводит к ошибке запуска.

## Данные и настройки

По умолчанию используется `backend/data/trips.sqlite3`, независимо от рабочего каталога.
Переменная `TRIPS_DB` задаёт другой путь (относительный путь отсчитывается от
рабочего каталога процесса):

```bash
TRIPS_DB=/tmp/driver-shift-log/trips.sqlite3 uv run --locked uvicorn app.main:app
```

База и родительские каталоги создаются при запуске. Таблица `trips` содержит
столбцы `id`, `start`, `end`, `amount`, `payment`, `commission`; `id` — первичный ключ.
Суммы хранятся как `INTEGER`, время — как ISO 8601 `TEXT` с исходным смещением.
Версия схемы хранится в `PRAGMA user_version` (сейчас `1`).

### Перенос из JSON

Остановите старый сервер, затем из `backend/` выполните:

```bash
uv run --locked python -m app.import_trips data/trips.json --database data/trips.sqlite3
```

Для другого исходного JSON укажите его путь вместо `data/trips.json`. Параметр
`--database` задаёт базу назначения и имеет приоритет над `TRIPS_DB`. Без него
используется `TRIPS_DB` или путь по умолчанию. Весь импорт выполняется одной
транзакцией: идентичные записи пропускаются, а конфликт `id` с другими данными
отменяет весь импорт. Неверные записи и повторяющиеся `id` внутри JSON отклоняются.
Исходный JSON не изменяется и остаётся доступным для повторного импорта.

При запуске сервера используйте тот же путь через `TRIPS_DB`. Старая переменная
`TRIPS_FILE` больше не выбирает активное хранилище: если задана только она, запуск
завершится с указанием перенести данные. `data/trips.json` остаётся исходным примером;
API читает и изменяет только SQLite. База и её служебные файлы исключены из Git.

`Trip` проверяет обязательные поля `id`, `start`, `end`, `amount`, `payment`,
`commission`. Время передаётся в ISO 8601 с часовым смещением; окончание должно быть
позже начала в абсолютном времени. Суммы — целые числа: `amount > 0` и
`0 <= commission <= amount`. Допустимые способы оплаты — `cash` и `card`.
Пустые идентификаторы, неизвестные поля и неявное преобразование сумм из строк,
дробей или логических значений отклоняются. Максимальное значение каждой суммы —
`9223372036854775807`, верхняя граница целого числа SQLite; превышение даёт HTTP 422.

`SqliteTripStore.list_trips()` читает и проверяет данные, `add_trip(trip)` добавляет
проверенную запись. Уже занятый `id` вызывает `DuplicateTripError`, содержащую
существующую поездку. HTTP-маршрут использует её для обработки повторной отправки.

Каждая операция открывает и закрывает своё соединение. Запись выполняется в
транзакции `BEGIN IMMEDIATE`; уникальность `id` обеспечивает база. Ошибка отменяет
транзакцию. Несколько потоков или процессов на одном хосте могут обращаться к одной
базе; SQLite выполняет записи по очереди и ждёт освобождения блокировки до 5 секунд.
Ошибка доступа или истечение ожидания возвращается как HTTP 503.

Для Docker подключайте постоянный том к **каталогу** базы, чтобы сохранялись и сама
база, и её журнальные файлы. Планируется один экземпляр backend на локальном диске;
общая SQLite-база на сетевом диске для нескольких серверов не предусмотрена.

## Поездки и сводка за день

Оба маршрута требуют параметр `date` в формате `YYYY-MM-DD`. День определяется
по времени **начала** поездки, переведённому в `Asia/Almaty`. Поездка через полночь
целиком относится к дню начала. Исходное часовое смещение в ответе сохраняется.

```bash
curl --fail 'http://127.0.0.1:8000/api/trips?date=2026-10-01'
curl --fail 'http://127.0.0.1:8000/api/summary?date=2026-10-01'
```

`GET /api/trips` возвращает массив поездок со всеми полями `Trip`, отсортированный
по времени начала от ранних к поздним (при совпадении времени — по `id`).

Ответ `GET /api/summary` после импорта примера:

```json
{
  "date": "2026-10-01",
  "trip_count": 2,
  "revenue": 3900,
  "commission": 585,
  "take_home": 3315,
  "cash_revenue": 1500,
  "card_revenue": 2400
}
```

`revenue` — выручка до комиссии; `commission` — сумма комиссий;
`take_home` — выручка за вычетом комиссии. `cash_revenue` и `card_revenue`
показывают выручку до комиссии по каждому способу оплаты.

Для дня без поездок возвращаются `[]` и сводка с нулевыми показателями.
Отсутствующая, невозможная или неверно отформатированная дата даёт HTTP 422.
Ошибка доступа или повреждение базы во время работы даёт HTTP 503 с сообщением
`Trip storage is unavailable`. Описание схем доступно в `/docs`.

## Добавление поездки

`POST /api/trips` принимает JSON-объект поездки:

```bash
curl -i 'http://127.0.0.1:8000/api/trips' \
  -H 'Content-Type: application/json' \
  -d '{"id":"t3","start":"2026-10-01T10:00:00+05:00","end":"2026-10-01T10:20:00+05:00","amount":2000,"payment":"cash","commission":300}'
```

- `201 Created`: новая поездка сохранена; тело ответа содержит сохранённую поездку.
- `200 OK`: поездка с тем же `id` и данными уже существует; возвращается исходная
  запись, новая строка не создаётся, сводка не меняется.
- `409 Conflict`: `id` уже занят поездкой с другими данными. Ответ:
  `{"detail":"Trip ID already exists with different data"}`. Исходная запись сохраняется.
- `422 Unprocessable Entity`: данные не прошли проверку. Массив `detail` содержит
  расположение ошибки (`loc`) и описание (`msg`). Например, нулевая сумма даёт
  `loc: ["body", "amount"]` и `msg: "Input should be greater than 0"`.
- `503 Service Unavailable`: запись не удалась; запрос можно повторить с тем же `id`.

Клиент создаёт `id` один раз и сохраняет его при повторных попытках отправки.
Разные `id` считаются разными поездками, даже если остальные поля совпадают.
Время сравнивается как момент времени: `08:10+05:00` и `03:10Z` для одной даты
эквивалентны. При повторе ответ сохраняет часовое смещение исходной записи.
Одновременные повторы, в том числе из разных процессов на одном хосте, создают
только одну запись.

## Тесты

```bash
uv run --locked python -m unittest discover -s tests -v
```

Проверяются валидация, импорт примера, сохранение и повторное открытие,
откат транзакций, ограничения SQL, повреждённые данные, настройка пути,
запуск приложения и добавления из разных потоков и процессов.
API-тесты дополнительно проверяют дневные итоги,
пустые дни, границы дня в `Asia/Almaty`, порядок поездок и ошибки запросов,
создание, повторы, конфликты идентификаторов и одновременные POST-запросы.
Запись в тестах выполняется только во временных каталогах.
